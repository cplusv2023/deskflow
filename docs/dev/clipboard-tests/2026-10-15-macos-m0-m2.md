# macOS 按需剪贴板 M0 至 M2 验证记录

日期：2026-10-15，Asia/Shanghai。分支为 `macos`，基于 Ubuntu 提交
`0f08f3111573eb0d0f01e0189baa8c104bd3ffcc`，测试使用包含本次 Mac 实现的未提交工作区。

**M0 至 M2 的基础验收通过**：本用户 FSKit 挂载、挂载后的范围测试，以及 Finder
原生 Cmd+V 均已完成。模拟源按偏移生成内容，没有完整源文件；这次结果不表示
真实 Ubuntu↔Mac 网络互通、完整 M3/M4 或 M5 Deskflow 集成已经完成。
用户反馈后的产品方向已调整：FUSE 保留为可选原型和验收参照，不作为普通用户
强制依赖；File Provider 为待原型验证的原生后端候选，见
[产品后端调整](../clipboard-macos-progress.md#产品后端调整用户反馈)。

## 环境和构建

| 项目 | 本机状态 |
| --- | --- |
| 系统 | macOS 27.0.1，build 26A434，arm64 |
| 工具链 | AppleClang 21.0.0，SDK 27.0，CMake 4.4.4，Ninja 1.13.2 |
| 文件系统 | macFUSE 5.4.0，`pkg-config fuse3` 为 3.18.2，使用 FSKit 后端 |
| FUSE3 SDK | `/usr/local/lib/pkgconfig/fuse3.pc` |
| 主工程依赖 | Homebrew Qt 6.11.2，OpenSSL 路径 `/opt/homebrew/opt/openssl@3` |
| 独立原型 | `build/macos-clipboard/`，不需要 Qt |
| 主工程 | `build/macos-core/`，Debug/Ninja，可选原型开启，安装包和 macOS bundle 关闭 |

初始 macFUSE 5.1.3 环境中，20 秒探测结束仍未挂载，stderr 为空。该失败记录仍在
`tmp/clipboard-macos/fsKit-attempt/`，不与后续成功结果合并。更新到 5.4.0 后，通过
系统设置“通用 → 登录项与扩展 → 按类别 → 文件系统扩展”启用 macFUSE，实际挂载
随后成功。“按应用”界面的无效开关有对应的维护者说明，建议使用“按类别”入口。
[macFUSE issue #1194](https://github.com/macfuse/macfuse/issues/1194)

挂载命令显式指定 `backend=fskit`；没有静默切换到内核扩展，也没有使用
`allow_other`。`FUSE_DARWIN_ENABLE_EXTENSIONS=0` 保留可移植 FUSE3 回调签名，
`NO_SYSTEM_FROM_IMPORTED` 保证 FUSE3 头文件优先于默认路径中的 FUSE2 版本。

独立构建与挂载测试：

```sh
cmake -S src/apps/clipboard-prototype -B build/macos-clipboard -G Ninja \
  -DCMAKE_BUILD_TYPE=Debug -DPython3_EXECUTABLE=/opt/homebrew/bin/python3 \
  -DCLIPBOARD_PROTOTYPE_DESKTOP_TESTS=ON
cmake --build build/macos-clipboard --parallel 4
ctest --test-dir build/macos-clipboard --output-on-failure -R '^clipboard_prototype_mount$'
```

`build/macos-core/Testing/Temporary/LastTest.log`。根 CMake 的测试注册只解决可发现性，
不会把原型功能接入 core 的握手、路由或生命周期。

正文请求按文件分布为：hello 一次、Unicode 文本一次、payload 十七次、large
1025 次。空文件不需要正文请求。发布期间和粘贴前有 `getattr` 等元数据查询，
没有正文读取；最后一个 large 请求为 offset 268435456、length 123。

生成源只按实际请求生成字节，原型未建立完整磁盘源文件或完整中间缓存，Finder
直接形成目标文件。上述约 0.676 秒只是本地生成源的首末读取区间，不能用来宣称
真实网络吞吐或用户操作的完整耗时。后续重复 Finder 复制期间已补充源进程 RSS
定时采样，最大观测值为 15536 KiB，原始记录为 `rss-samples.json`；实际采样间隔
受进程调度和读取开销影响，不能称为系统实际峰值。Finder 的取消、预览和缩略图
行为仍未计为通过。

## 原生格式与替代后端补测

M3 在本机 general pasteboard 的基本路径已有实际应用证据：TextEdit 纯文本
复制后由工具读出，工具发布的 HTML 在 TextEdit 粘贴后保留样式，TextEdit 复制
的 RTF 经适配转为 HTML；Preview 接收工具发布的 PNG，并再次复制供工具读取，
160×96 图像与源图逐像素一致。输出位于 `tmp/clipboard-macos/native-formats/`，
包括 `textedit-source.txt`、`html-pasted.rtf`、`textedit-source.html`、
`sample.png`、`preview-source.png` 及各方向 JSONL 日志。PNG 字节编码可以不同，
验收比较的是像素。本轮没有据此将 M3 的跨机、多应用和后台权限全部标为完成。

为评估无 FUSE 的方案，另在 macOS 27.0.1 测试了纯 `NSFilePromiseProvider`：
只发布 promise 到 general pasteboard，不发布 file URL，不预先生成文件。
Finder Cmd+V 无目标文件，编辑菜单“粘贴”禁用，`writeCallbacks=0`；结果位于
`tmp/clipboard-macos/file-promises/finder-result.json`，实验说明和程序在同目录。
这只说明本机版本的该场景未通过，不能泛化到所有版本。File Promises 继续作为
拖放补充候选；File Provider 还需独立的签名 appex 测试，尚无其 Finder 粘贴、
系统缓存、全文件回调、取消或部署体验的通过记录。

## 证据与未覆盖范围

忽略目录 `tmp/clipboard-macos/finder-20261015/` 保留：

- `before-paste.json`：粘贴前时间、零正文请求及发布器四个条目的记录。
- `clipboard.jsonl`：AppKit 文件 URL 发布事件。
- `files.jsonl`：挂载、元数据、打开、范围请求、返回和释放的时间线。
- `result.json`：文件大小、哈希、权限、空目录、请求预算及复制后 RSS 汇总。
- `rss-samples.json`：重复 Finder 复制时的定时 RSS 采样，最大观测值 15536 KiB。

原始大日志、挂载内容和目标文件不提交 Git。独立挂载测试已验证退出卸载；Finder
专用挂载的最终清理状态随后续补测记录，不从文件复制成功推断所有资源已回收。

尚未覆盖：系统实际峰值 RSS、Finder 中途取消、预览开关对照、超过 4 GiB 的整文件
原生复制，以及真实 Ubuntu↔Mac 双向传输。M3 已有平台格式与文件发送原型及上述
TextEdit/Preview 基本路径实测，仍需多应用和后台权限验证；M4 已有共享服务/Broker 和本地 JSONL 进程测试，
尚无完整平台组合、续租调度与网络故障矩阵；M5 的协商、认证数据连接、旧端适配
和 core 生命周期尚未实现。各阶段状态继续维护在
[macOS 进度文档](../clipboard-macos-progress.md)。
