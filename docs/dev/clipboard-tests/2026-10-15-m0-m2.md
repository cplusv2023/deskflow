# Ubuntu 按需剪贴板 M0 至 M2 验证记录

日期：2026-10-15，Asia/Shanghai。基线提交为 `c46781f19b1f5e39df67266665084de15f91b01c`，测试使用包含本次原型代码的未提交工作区。

M0 至 M2 已通过同机原型验证。数据源在本进程按偏移生成数据，作为 Mac 接口的模拟替身；这次结果不代表网络协议、Ubuntu 发送方向或真实 Mac 联调完成。

## 环境和构建

- Ubuntu 26.04.1、GNOME Shell 50.1、Wayland、XWayland 24.1.10、Nautilus 50.2.2。
- GCC 15.2、CMake 4.2.3、Ninja 1.13.2、libfuse3-dev 3.18.2、libX11 1.8.13。
- 普通用户 UID 1000，未使用 root 挂载或 allow_other。
- 独立构建目录为 `build/clipboard-prototype/`，主工程可选目标验证目录为 `build/clipboard-integrated/`。
- 主工程验证配置显式使用系统 Qt 6.10.2，并排除当前 Conda 搜索路径；两个原型目标本身不依赖 Qt。原有 `build/` 构建配置未改动。

独立构建与自动测试命令：

```bash
cmake -S src/apps/clipboard-prototype -B build/clipboard-prototype \
  -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCLIPBOARD_PROTOTYPE_DESKTOP_TESTS=ON
cmake --build build/clipboard-prototype --parallel 4
ctest --test-dir build/clipboard-prototype --output-on-failure
```

## 原生 Files 粘贴

测试使用两个专用目标目录。发布器通过显式 X11 连接拥有 CLIPBOARD，公告挂载点中的文件 URI。辅助脚本通过 AT-SPI 调用相应 Nautilus 窗口的 `view.paste`，没有调用绕过剪贴板的 `FileOperations2.CopyURIs`。

Nautilus 进程处于 Wayland 会话并连接 GNOME Shell 的 Wayland socket；该进程没有托管的 X11 窗口。剪贴板发布器连接 XWayland，Files 通过桌面桥接取得 GNOME 文件列表，实际日志出现 `x-special/gnome-copied-files` 请求。

| 文件 | 大小 | SHA-256 |
| --- | --- | --- |
| hello.txt | 86 B | `1d4a718e25d8d6b6a81d9a9225eab64bf0f1c24e734cf97c96c96eb6c46835d5` |
| empty.txt | 0 B | `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855` |
| nested folder/含 空格.txt | 12289 B | `f349c09173b29585045c5e7b94f8756abb9cde46bb4d052dfce8e8950438b041` |
| nested folder/payload.bin | 4194341 B | `63c20e0d8f4fb5e7f58f13c90e9a0b63d331fff1a3f0227c56f154fe82630e44` |
| large.bin | 268435579 B | `66c250955c4a76ed9d1f05ec6dcee7a978d07de01528e94c32632e75c4df7692` |

所有文件与独立计算的生成规则或固定文本校验一致，空目录 `nested folder/empty dir` 存在；复制后的普通文件权限为 0644，可继续编辑。

本次两次粘贴共返回 272642295 字节文件主体，日志包含 66567 个范围响应，最大请求为 4096 字节，观测到的最大同时请求数为一。模拟文件源 VmHWM 与 VmRSS 均为 5112 KiB。该数据是本机生成源的内存验证，不用于推断真实网络吞吐或延迟。

挂载后的目录项先可见，发布器只编码 URI，不读取正文。单文件的第一次正文读取出现在正常粘贴请求后。源数据由程序生成，无完整磁盘源副本；源进程只写请求日志，Files 直接写最终目标文件。

## 浏览和缩略图读取

增加 189 字节合法 SVG 作为缩略图样本，在同一专用源窗口分别验证以下设置：

| show-image-thumbnails | 实际主体读取 | 观察 |
| --- | --- | --- |
| never | large.bin 两次各 16384 B，共 32768 B | 浏览时的文件类型探测会读取头部，关闭缩略图不能阻止所有内容读取。 |
| always 后刷新 | large.bin 同样两次头部读取，加 preview.svg 的 189 B，共 32957 B | 缩略图触发真正的文件读取，未触发大文件全量下载。 |

只调用 FUSE 元数据操作时正文计数为零；Files 的类型探测和缩略图会额外调用 read。这两种情况分别记录，不把真实消费者读取归咎于元数据接口预下载。
